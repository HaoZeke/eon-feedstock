About eon-feedstock
===================

Feedstock license: [BSD-3-Clause](https://github.com/conda-forge/eon-feedstock/blob/main/LICENSE.txt)

Home: https://eondocs.org/

Package license: BSD-3-Clause

Summary: Algorithms for long time scales and potential energy surface exploration

Development: https://github.com/TheochemUI/eOn

Documentation: https://eondocs.org/index.html

The EON software package contains algorithms used primarily to model the
evolution of atomic scale systems over long time scales. This version is
built with metatomic, xtb, and serve mode support.

Installing eon
==============

Installing `eon` from the `metatensor` channel can be achieved by adding `metatensor` to your channels with:

```
conda config --add channels metatensor
conda config --set channel_priority strict
```

Once the `metatensor` channel has been enabled, `eon` can be installed with `conda`:

```
conda install eon
```

or with `mamba`:

```
mamba install eon
```

It is possible to list all of the versions of `eon` available on your platform with `conda`:

```
conda search eon --channel metatensor
```

or with `mamba`:

```
mamba search eon --channel metatensor
```

Alternatively, `mamba repoquery` may provide more information:

```
# Search all versions available on your platform:
mamba repoquery search eon --channel metatensor

# List packages depending on `eon`:
mamba repoquery whoneeds eon --channel metatensor

# List dependencies of `eon`:
mamba repoquery depends eon --channel metatensor
```




Updating eon-feedstock
======================

If you would like to improve the eon recipe or build a new
package version, please fork this repository and submit a PR. Upon submission,
your changes will be run on the appropriate platforms to give the reviewer an
opportunity to confirm that the changes result in a successful build. Once
merged, the recipe will be re-built and uploaded automatically to the
`metatensor` channel, whereupon the built conda packages will be available for
everybody to install and use from the `metatensor` channel.
Note that all branches in the conda-forge/eon-feedstock are
immediately built and any created packages are uploaded, so PRs should be based
on branches in forks, and branches in the main repository should only be used to
build distinct package versions.

In order to produce a uniquely identifiable distribution:
 * If the version of a package **is not** being increased, please add or increase
   the [``build/number``](https://docs.conda.io/projects/conda-build/en/latest/resources/define-metadata.html#build-number-and-string).
 * If the version of a package **is** being increased, please remember to return
   the [``build/number``](https://docs.conda.io/projects/conda-build/en/latest/resources/define-metadata.html#build-number-and-string)
   back to 0.
